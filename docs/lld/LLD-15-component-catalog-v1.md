# LLD-15 — каталог компонентов реестра v1: грид, доска, деталка, галерея, карта

Дата: 2026-07-02. Автор решений: Fable. Реализация: Sonnet 5 по документу.
Родитель: LLD-05 (слои реестра), LLD-14 (UI-как-данные, инвариант I-6). Наполняет
ЗАКРЫТЫЙ реестр конкретным набором под Airtable/Jira-подобные сценарии + медиа/гео.

**Мотив (требование фаундера).** Реестру нужен рабочий стартовый набор «лёгких,
но настоящих» контролов: грид (Airtable), доска (Jira), деталки, модалки, плюс
карта/геолокация и фото/видео. Уровень — v1: покрыть демо Legal/KnowVault/
дебиторки, не строить полный Airtable.

**Границы для исполнителя.** Sonnet НЕ решает сам: какие типы идут в ЯДРО/DSL
(§3 — `geo` новый тип, медиа на существующем `file`, остальное number+format;
ревью Fable, это модель данных); что редактирование в гриде и перенос на доске —
это governed workflow-transition/update через choke point, НЕ прямая мутация
(§2, I-2); что карта/видео/фото рендерятся ИЗ контура, подложка карты — конфиг
узла, НЕ внешний CDN в прод (§4, принцип H4, air-gapped fallback обязателен);
состав v1 vs «позже» (§1, фиксирован). Все компоненты — узлы реестра под I-6.

---

## 1. Состав v1 по уровням (решение)

**Atoms** (к базовым LLD-05: Input, Select, Money, Badge, StatusChip, DateTime,
Bool, RefLink) добавить:
- `Media` — превью `file`-поля по mime (img/video/pdf/иное) + lightbox/нативный
  `<video>`, источник — blob из контура (files-механика есть).
- `GeoPoint` — координаты + мини-превью точки.
- `Tags` — мультизначный enum/ref (chips).
- `Avatar` — `ref[core.User]` (инициалы/фото).
- `Progress`, `Rating`, `Percent`, `Duration` — над `number` + format-подсказка
  из meta (НЕ новые типы ядра — рендер по format).
- `Link`/`Email`/`Phone` — типизированный текст с безопасным действием
  (схема URL проверяется, I-6).
- *Позже:* Color, sparkline, inline-formula.

**Molecules** (к LLD-05: FieldRow, RecordCard, ApprovalCard, TimelineItem,
DashboardTile):
- `Modal`, `Drawer` — форма/деталка во всплывашке/боковой панели.
- `Toolbar` — поиск + фильтр + сортировка + группировка над коллекцией.
- `Pagination`, `Tabs`, `EmptyState`.
- `ConfirmDialog` — подтверждение как КОМПОНЕНТ реестра (НЕ нативный
  `confirm()` — нативные диалоги блокируют и вне I-6).
- *Позже:* Accordion, SplitView, CommandPalette.

**Organisms — виджеты данных (сердце v1):**
- `KTable` (грид Airtable-стиля): колонки из meta; сортировка/фильтр/группировка;
  выбор строк; пагинация/виртуализация для больших наборов. Правка v1 — через
  деталку-`Drawer` (инлайн-cell-edit — «позже»).
- `KBoard` (Jira-доска): канбан-колонки по workflow-статусу; карточка =
  RecordCard; перенос между колонками = **инициирует workflow-transition**
  (governed, HITL как есть — §2), не прямую смену статуса. WIP-лимиты/swimlanes
  — «позже».
- `KDetail` (деталка): поля + таймлайн + действия + вложения.
- `KInbox` (очередь HITL) — LLD-05.
- `KGallery` (медиа-плитка): `file`-поля img/video плиткой + lightbox/плеер,
  всё из blob контура.
- `KMap` (гео): точки записей на карте; клик → `KDetail` в `Drawer`; подложка —
  §4.
- *Позже:* `KCalendar` (R3 calendar-view), `KTimeline`/Gantt, `KPivot` (сводные).

**Faces (примеры-экраны как схемы LLD-14 §1):** `TableFace`
(KTable+Toolbar+Modal-деталка = «база данных»), `BoardFace` (KBoard),
`MapFace` (KMap+список), `GalleryFace` (KGallery) — плюс SearchFace/RiskCardFace
(LLD-05), ChatFace (LLD-06). Face = преднастроенное дерево, не новый код.

## 2. Правка через governance, не в обход (I-2)

**Решение (не обсуждается).** Ни грид, ни доска не мутируют состояние напрямую:
- KTable-правка → обычный `update` через SDK/headless → Permission Engine +
  журнал (валидация, ABAC, undo бесплатно). Ячейка, которую актор не вправе
  менять, — read-only по meta, не «серверный отказ после клика».
- KBoard drag между колонками → соответствующий **workflow-transition** записи
  (если перехода нет — перенос отклонён в UI по meta; если требует
  approval(Role) — паркуется в HITL, карточка показывает pending). Доска
  ОТРАЖАЕТ governance, а не задаёт его (born-agentic, как SalesBot).

## 3. Типы полей: что в ядро, что нет (ревью Fable — модель данных)

- **Медиа — на существующем `file`** (есть, + mime). Множественные вложения =
  список файлов. *Зависимость/вопрос:* если DSL не имеет мультизначного
  (`list[...]`) типа — множественные вложения и `Tags` требуют его; это ЯДРОВЫЙ
  гэп, зафиксировать (TECHDEBT + вопрос), НЕ хакать одиночным полем.
- **Гео — новый скалярный тип `geo { lat, lng }`** (аддитивно, I-1; в ряд
  money/datetime). *Обоснование:* фундаментальный тип данных, не рост грамматики
  ЛОГИКИ (дисциплина N5 про логику, не про типы); без него гео — два несвязанных
  числа без семантики для KMap/валидации. Ревью Fable.
- **Progress/Rating/Percent/Duration/Tags-визуал — НЕ новые типы**: number/enum
  + format-подсказка в meta, рендер выбирает atom. Ядро не растёт.

## 4. Медиа и карта — из контура, не из интернета (принцип H4)

**Решение (не обсуждается).**
- Фото/видео — нативные `<img>`/`<video>` из blob файлов ВНУТРИ периметра;
  ноль внешних медиа-сервисов/CDN, ноль транскодинга в v1 (отдаёт как есть).
- Карта — подложка тайлов из **конфига узла** (`--map-tiles <url>`), по умолчанию
  может отсутствовать: в air-gapped-контуре KMap деградирует до координатной
  сетки/списка точек, НЕ тянет публичный тайл-сервер (тот же принцип, что
  «прод = локальная модель»: внешний ресурс — явный флаг оператора, не дефолт).
- Тайл-URL и медиа-источники — конфиг/данные узла, НЕ из пользовательского
  ввода/агента (I-6: значение поля не становится src произвольного ресурса —
  src проверяется схемой/whitelist).

## 5. Приёмочные тесты (фиксированы)

1. `TestKTableFromMeta` — грид строит колонки из meta; сортировка/фильтр/
   группировка работают; правка ячейки без прав — read-only по meta.
2. `TestKBoardDragIsTransition` — перенос карточки = workflow-transition
   (журналируется); перенос без валидного перехода отклонён в UI; переход с
   approval → pending в HITL, не молчаливая смена статуса.
3. `TestKGalleryAndVideoFromBlob` — img/video рендерятся из файлов контура;
   ни одного внешнего запроса.
4. `TestKMapAirgapFallback` — без `--map-tiles` KMap показывает точки без
   внешней подложки (fallback), не обращается в интернет; с конфигом — тайлы
   из указанного URL.
5. `TestGeoTypeRoundtrip` — поле `geo` валидируется (lat/lng диапазоны),
   реплеится, доступно KMap; старый журнал без geo реплеится (I-1).
6. `TestMediaSrcNotFromUserInput` — значение поля со «злым» URL/HTML не
   становится src ресурса/разметкой (I-6, стык с LLD-14 §1).
7. Golden/I-1: паки без новых типов/компонентов работают как прежде.
