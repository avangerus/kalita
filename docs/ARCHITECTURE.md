## Что такое kalita

Один Go-бинарник, на котором собираются governed-системы: AI-агенты и люди
работают под строгими правами, всё событийно-журналируется и обратимо.
DSL — **декларативный словарь бизнес-понятий**, не язык программирования.

## Один закон: свободного CRUD нет

Любое изменение мира — это **именованная команда**, записанная **фактом**.
Нельзя «поменять что угодно». Можно только «сделать вот это, названное».
Много мелких именованных действий > одна большая CRUD-функция-монстр.

## Поток: команда → факт (двое ворот)

```
команда (императив, извне, отвергаема)
   │
   ▼  ВОРОТА 1 — контракт: вход по схеме команды (структура, типы)
   │
   ▼  ЛОГИКА:  декларативная (без кода)  ИЛИ  воркер (Python-адаптер)
   │           воркер считает ПРЕДЛОЖЕНИЕ изменений, в хранилище не пишет
   ▼
   ▼  ВОРОТА 2 — права + инварианты домена (guard/required/where)
   │
   ▼
факт в журнал  (или error-факт при отказе — I-3, молча не теряем)
```

Одна команда = одна атомарная пачка изменений = один факт (или один error-факт).

## Где что живёт (Ports & Adapters)

- **Домен** = entity + её инварианты. Декларативно, читаемо. Здесь правила. ← агрегат
- **Порт** = контракт команды в DSL (имя, входы, сущность, кто может).
- **Адаптер** = Python-воркер. Свободен внутри, наружу лезет только через порт.
- **Обработчик** = choke point (Permission Engine + валидация). Единственная точка записи (I-2).
- **Факты** = журнал (append-only, hash-chain, обратимо).

**Правило валидации:** инварианты держит ДОМЕН (декларативно), не воркер.
Воркер считает предложение — домен решает. Правила не прячем в код.

## Два режима: порядок наружу, мощь внутрь

- **Base** (всем) — маленький читаемый язык. Сломать нельзя. Прочитал — понял целиком.
  `entity` · `reference` · `workflow` · `permission` · `event` (команда) · `dashboard`
- **Extended** (сертифицированным/партнёрам) — больше верёвки.
  `worker` · кастомная команда · `subscription` · федерация · сырые выражения
- Гейт **технический, не на слове:** пак объявляет tier; extended-конструкты
  компилятор отвергает, пока владелец узла явно не включил extended-режим.
  Сертификат/партнёрство — бизнес-слой поверх.

## Admission gate: когда добавлять конструкт

Прежде чем ввести новое слово языка, спроси:
- **Узнаваемое бизнес-существительное, кросс-вертикальное, примитив?** → редко, конструкт.
- **Кастомная логика?** → всегда воркер. Никогда — новая грамматика.

По умолчанию — **не добавлять**. Предпочитать вычитание. (Salesforce убил 2 из 3
способов автоматизации — это и есть дисциплина, а не слоган.)

## Обязательства по вычитанию (исполнить, не только перечислить)

- заморозить словарь глаголов прав (закрытый список, не растёт);
- один pending-intent вместо трёх (definition.proposed / approval / shadow → один примитив);
- faces → именованные схемы (убрать лишний слой).

## Инварианты (неизменны)

I-1 аддитивность · I-2 одна точка записи · I-3 ошибка — событие · I-4 секреты
только узел/воркер · I-5 оффлайн-провабельность (replay не зависит от внешних
узлов) · I-6 UI из закрытого реестра.
